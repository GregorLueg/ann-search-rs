## Standard indices benchmarks and parameter gridsearch

Below are all of the standard indices shown and their performance. These
are run via:

```bash
# Run with default parameters
cargo run --example gridsearch_<INDEX> --release -- --distance euclidean

# Override specific parameters
cargo run --example gridsearch_<INDEX> --release -- --distance cosine

# Available parameters with their defaults:
# --n-samples 150_000
# --dim 32
# --n-clusters 25
# --k 15
# --seed 42
# --distance euclidean
# --data gaussian
# --intrinsic-dim 16   (lowrank data only)
```

The data sets are there to give a feel for how each index behaves against
different kinds of structure. Don't extrapolate ideal parameters for your own
problem from them. This is a single run, so exact times vary, but the trends
should reproduce on your hardware. A subset of the indices also supports
Manhattan distance.

### Annoy

`Approximate nearest neighbours Oh Yeah`. A forest of random-projection trees.
Index size scales with the number of trees. This version drops the original's
on-disk querying and is a pure in-memory index.

**Tunable parameters:**

- *Number of trees (nt)*: The number of trees to generate in the forest
- *Search budget (s)*: The search budget per tree. If set to auto it uses
  `k * n_trees * 20`; versions with a `10x` or `5x` (i.e., less) are also shown.

Self is queried with the default search budget.

### BallTree

A metric tree partitioning points into nested hyperspheres. Where Annoy leans
on random projections, BallTree prunes with the triangle inequality, so a single
tree does the job of a forest.

**Tunable parameters:**

* *Search budget (s)*: The percentage of the total nodes/points to inspect
  during the query. If not provided, it will default to `5%`.

Self is queried with the default search budget.

### HNSW

Hierarchical navigable small worlds. A layered proximity graph: expensive to
build, fast to query, and modest in memory for what it gives you.

**Tunable parameters:**

- *M (m)*: The number of connections between layers
- *EF construction (ef)*: The budget to generate good connections during
  construction of the index.
- *EF search (s)*: The budget for the search queries.

Self is queried with `s=100`.

### IVF

Inverted file index. k-means Voronoi cells over the data, with the query
scanning only the cells nearest to it. Smallest in-memory footprint of the
unquantised indices.

**Tunable parameters:**

- *Number of lists (nl)*: The number of independent k-means clusters to
  generate. If the structure of the data is unknown, `sqrt(n)` is the usual
  heuristic.
- *Number of probes (np)*: The number of clusters to probe during search.
  Numbers here tend to be `sqrt(nlist)` or up to 5% of the nlist.
- *k-means training (`KMeansTrainingParams`)*: The clustering step itself is
  tunable (iterations, subsample size, initialisation). Left at its defaults
  across this grid.

Self query was done with `2 * sqrt(nlist)`.

### Kd forest

A forest of randomised Kd-trees. Each tree splits on a coordinate axis drawn at
random from the highest-spread dimensions, which is what keeps the trees
diverse. A split is one coordinate comparison rather than a full dot product, so
traversal and build are both cheap.

**Tunable parameters:**

- *Number of trees (nt)*: The number of trees to generate in the forest
- *Search budget (s)*: The search budget per tree. If set to auto it uses
  `k * n_trees * 20`; versions with a `10x` or `5x` (i.e., less) are also shown.

Self is queried with the default search budget.

### kMkNN

k-means nearest neighbour index. Voronoi cells like IVF, but the triangle
inequality prunes distance computations rather than the search skipping cells
outright, so this one is **exact**: it returns what a brute-force scan returns
and recall is always 1.0.

Its home ground is low-to-moderate dimensionality (roughly 20-100), where
distances still have spread and cluster structure means something. On
high-dimensional isotropic data the bounds go slack and it degenerates towards
an exhaustive scan.

Cosine distance L2-normalises at build time and runs internally in Euclidean
space. Squared Euclidean on the unit sphere is monotone in cosine distance, so
the triangle inequality stays valid.

**Tunable parameters:**

- *Number of lists (nl)*: The number of k-means clusters to generate. As with
  IVF, `sqrt(n)` is a reasonable default. Fewer clusters means larger cluster
  radii and weaker pruning; more clusters tightens the bounds but grows the
  centroid scan at query time.
- *k-means training (`KMeansTrainingParams`)*: Same knob as IVF, left at its
  defaults here.

### LSH

Locality sensitive hashing. Fast, with a memory footprint that grows with the
table count.

Each table holds `nb / q` orthogonalised random projections. A projection is
turned into a slot by binary-searching quantile boundaries fitted on a
subsample of the data, and the code is the concatenation of those slots. Fitting
the boundaries to the data is what keeps buckets balanced: plain SimHash puts
every hyperplane through the origin, so on data carrying a large shared mean
offset (foundation-model cell embeddings being the obvious case) the sign is
decided by the offset and nearly everything lands in one bucket.

**Tunable parameters:**

- *Number of tables (nt)*: The number of independent hash tables to generate.
  More tables improve recall at the cost of query time and memory.
- *Number of bits (nb)*: The bit resolution of the hash functions, so `2^nb`
  addressable buckets per table. Higher values create finer partitions but may
  reduce collision rates. Capped at 20, since the bucket table is directly
  addressed.
- *Slot bits (q)*: How many bits each quantised projection contributes, which
  fixes the projections per table at `nb / q`. At `q=1` a projection is a single
  bit, the sign against its median, which is the angular family cosine wants. At
  `q>=2` it is quantised into `2^q` levels instead, which makes the hash
  sensitive to vector magnitude. Squared Euclidean needs that, because distance
  on unnormalised vectors is driven by magnitude as much as by direction.
  Defaults to 1 for cosine and 2 for Euclidean. Pushing it higher is usually a
  loss: it starves multi-probe of projections to perturb.
- *Number probes (n)*: How many additional buckets to explore per hash table.
  A probe shifts one projection into an adjacent slot, ordered by how close the
  query sits to the boundary it crosses, so the most uncertain projection moves
  first. There are `2 * nb / q` single-slot shifts available; anything past that
  starts combining pairs. `nb / q` is a good starting point.
- *Max candidates (s)*: The search budget, counted as unique candidates scored
  across all tables and probes. Set to 'auto' for full search or a fixed value
  (e.g., 2k) for faster queries with lower recall.

### NNDescent

NN-Descent, heavily inspired by the excellent
[PyNNDescent](https://github.com/lmcinnes/pynndescent). A random-projection
forest seeds a kNN graph, then local joins over neighbours-of-neighbours refine
it until the improvement rate falls below `delta`. Good all-rounder, and the
only CPU index here that hands back a self-kNN graph without a search pass. See
[the kNN-graph benchmarks](benchmarks_knn_graph.md) for that path.

Three rows per configuration: `(query)` for the beam search against held-out
data, `(self)` for the full self-kNN via beam search, and `(extract)` for the
descent's own graph handed back as-is. The gap between `(self)` and `(extract)`
is exactly what the beam search buys on top of the graph.

**Tunable parameters:**

- *Graph degree (k)*: Neighbours per node in the built graph. Defaults to `30`.
  Also the ceiling on what `(extract)` can return.
- *Number of trees (nt)*: Trees used for the initialisation. Auto defaults to
  `min(5 + round(n^0.25), 12)`.
- *Search budget (s)*: Budget for the graph exploration at query time. Defaults
  to `k * n_trees`.
- *Delta*: Early-stop threshold on the fraction of edges still improving.
- *Max iterations* and *max candidates*: Hard caps on the descent loop and on
  the per-node candidate pool. Left at their defaults across this grid.
- *Diversify probability (dp)*: Post-descent RNG-rule prune, inspired by
  PyNNDescent. For each node, the forward k-NN row is merged with reverse
  edges, then candidates are pruned when closer to an already-kept
  neighbour than to the origin (Bernoulli coin with probability `dp`).
  Short rows get topped up from the pruned tail so out-degree stays at
  `k`. Recovers cross-cluster connectivity on well-clustered data at a
  small query-time cost; on uniform data it costs a bit of recall too.

### NSG

`Navigating Spreading-out Graph`. Takes an approximate kNN graph, built here
internally by NNDescent, and thins it with the MRNG rule: a candidate edge is
dropped if some already-kept neighbour sits closer to it than the origin does.
That leaves each node with a spread-out set of directions rather than a cluster
of near-duplicates pointing the same way. Pruning alone can strand nodes, so a
DFS from a single navigating node (the data point closest to the centroid) walks
the graph afterwards and wires any unreachable node back to its nearest reachable
predecessor. Queries are a greedy beam search. See
[Fu et al., PVLDB 12(5), 2017](https://arxiv.org/abs/1707.00143).

**Tunable parameters:**

- *Max degree (R)*: Out-degree cap after MRNG pruning. On clustered data the
  occlusion rule alone can collapse a node down to a handful of edges, so nodes
  left short get topped back up from their nearest kNN entries. `R` is therefore
  the real degree for nearly every node, not just a ceiling.
- *Build beam width (L_build)*: Beam for the per-node candidate search over the
  input kNN graph. Wider gives the prune more to choose from and costs build
  time.
- *Candidate cap (C)*: Ceiling on the candidate set before pruning, which bounds
  the per-node prune cost. Fixed at `500` here and rarely worth touching.
- *kNN graph degree (knn_k)*: Degree of the internal NNDescent graph. Fixed at
  `32` here. Ignored if you hand NSG a kNN index you already built.
- *EF search (ef)*: Beam width at query time. `auto` is `100`.

One entry point is not enough at scale. On clustered data a single-seed walk from
the navigating node runs out of beam crossing between clusters and a slice of
queries terminates in the wrong region entirely. So on top of the navigating node
the query seeds `sqrt(n)` entry points strided across the dataset, clamped to
`[64, 512]`. Each seed costs one distance evaluation and the far ones never get
expanded.

Self is queried with the default `ef_search` (100).

### Relative NNDescent

RNN-Descent folds the RNG prune straight into the NNDescent update loop, so a
single pass hands you a graph that's already search-ready. Where NSG needs a full
kNN graph materialised first and then a second pass over it, this never builds
one. Start from a random graph of out-degree `S`, then alternate: prune each
node's adjacency by the RNG rule, add the surviving reverse edges back, repeat.
Query-time entry points come from a small kd-forest built alongside the graph,
`min(5 + n^0.25 / 2, 16)` trees by default, queried once per query rather than
per hop. See
[Ono & Matsui, ACM MM 2023](https://arxiv.org/abs/2310.20419).

**Tunable parameters:**

- *Seed degree (S)*: Out-degree of the initial random graph.
- *Max degree (R)*: Per-node adjacency cap once reverse edges are folded in.
- *Outer rounds (T1)* and *inner passes (T2)*: `T1` rounds of `T2` update passes
  each. Paper defaults are `T1=4`, `T2=15`; the grid here runs `T2=10` to keep
  build times sensible.
- *Search degree (K)*: How many of a node's neighbours get expanded per hop at
  query time. This is the knob most worth sweeping. `auto` is `min(32, R)`;
  setting it to `R` walks the whole adjacency and buys recall at the cost of
  query speed.
- *EF search*: Beam width at query time, `100` by default and left there across
  the whole grid so the `K` sweep is the only thing moving.

Self is queried with the default `ef_search` and `K`.

### SOAR

`Spilling with Orthogonality-Amplified Residuals`. An IVF index where every
vector is written into two cells rather than one: its nearest centroid, and a
second chosen so its residual points somewhere the first one does not. Cover a
point from two directions and a query approaching from either side finds it
without probing wider. See
[Sun et al., NeurIPS 2023](https://arxiv.org/abs/2404.00774).

Read these tables by recall against **query time**, not against `nprobe`. At a
fixed `nprobe` a spilled index scans roughly twice the candidates, so a
recall-versus-`nprobe` reading flatters it and answers nothing. Sweep A varies
`nlist` against plain IVF at the same `nlist`; sweep B holds `nlist` and varies
the rule.

**Tunable parameters:**

- *Number of lists (nl)*: As IVF. The sweep runs `0.5x`, `1x`, `2x` and `4x`
  `sqrt(n)`, wider than the plain IVF grid: modelling query cost as
  `nlist*dim + nprobe*(n/nlist)*dim` puts the optimum near `sqrt(nprobe * n)`,
  and spilling pays in the fine-cell regime above it.
- *Number of probes (np)*: As IVF, but skewed low here. `np=1` is the fairest
  head-to-head, since a spilled index at `np=1` scans about the same candidate
  count as a plain one at `np=2` over a different set of points.
- *Rule*: How the second cell is picked.
  - `Nearest`: plain second-nearest centroid. The control.
  - `Shifted { mu }`: nearest centroid to `x + mu * (x - c_1)`. Derived for
    squared Euclidean; `mu = 0` degenerates to `Nearest`. Sensible range
    `0.2-1.0`.
  - `Orthogonal { lambda }`: the published loss
    `||r'||^2 + lambda * (r' . r_hat_1)^2`. Derived for MIPS on the unit
    sphere, so cosine is its home ground.
- *k-means training (`KMeansTrainingParams`)*: As IVF, left at defaults.

The self-query path is not benchmarked here. Its ground truth is an
`O(n^2 * dim)` exhaustive self-query and it does not discriminate between the
rules, which is what both sweeps are for. `query_soar_self` is covered by the
unit tests instead.

### Vamana

The graph behind DiskANN. A directed navigable graph seeded with random
long-range edges, refined over two passes with a beam search and alpha-pruning.
The entry point is the dataset medoid. This is the in-memory variant.

**Tunable parameters:**

- *Max degree (R)*: Maximum out-degree per node in the graph.
- *Build list size (L_build)*: Beam width during construction.
- *Alpha pass 1 / pass 2*: Pruning slack per refinement pass. Pass 1 is
  typically `1.0` (plain RNG rule); pass 2 goes above it to keep longer edges
  that the strict rule would occlude. Fixed across this grid.
- *Search list size (ef_search)*: Candidate list size at query time. Defaults
  to `75`.

Self is queried with `ef_search=75` (default value).
